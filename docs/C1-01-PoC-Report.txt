C1-01 (PoC) — SERVER.JS BEHAVIOR VALIDATION
================================================================================

Date:        2026-09-30
Status:      VERIFIED (standalone, not yet in F5)
Owner:       Implementation agent

GOAL
    Prove that server.js, as a standalone component, correctly:
      - parses --f5
      - reads config.json and tsconfig.json
      - locates esbuild from the stable location
      - runs esbuild synchronously
      - produces debug.js, debug.js.map, index.html
      - serves those files over HTTP on 127.0.0.1:<port>
      - rejects path traversal
      - does NOT launch a browser in --f5 mode
      - launches the browser in direct mode
      - terminates the browser process tree on SIGINT
      - releases the port on exit
      - fails clearly when the port is occupied

METHOD
    1. Created a sandbox at C:\Users\Navid\source\repos\ServerJsTest.
    2. Copied esbuild.exe to obj/TypescriptBridge/tools/esbuild/win-x64/.
    3. Wrote config.json, tsconfig.json, ts/app.ts, server.js.
    4. Ran `node --check server.js` (syntax).
    5. Ran `node server.js --f5` in the background.
    6. Verified HTTP responses.
    7. Ran `node server.js` (direct mode).
    8. Verified browser launch and shutdown.
    9. Occupied port 45000 and re-ran server.js.

RESULTS
    Syntax check:                    PASS
    --f5 mode starts server:         PASS
    --f5 mode does NOT launch browser: PASS
    GET /index.html:                 200 text/html
    GET /debug.js:                   200 application/javascript
    GET /debug.js.map:               200 application/json
    Path traversal (/../config.json): rejected
    Direct mode launches browser:    PASS
    userDataDir created:             PASS
    SIGINT releases port:            PASS
    SIGINT kills browser tree:       PASS
    Port conflict fails clearly:     PASS (exit 1)

FILES INVOLVED
    server.js              (13450 bytes)
    config.json            (new shape)
    tsconfig.json          (compilerOptions.target)
    ts/app.ts
    obj/TypescriptBridge/tools/esbuild/win-x64/esbuild.exe

NOTES
    In F5 mode, launch.json is owned by Visual Studio. server.js only
    starts the HTTP server.
    In direct mode, server.js launches the browser itself and manages
    its lifetime.
    The debug output directory is cleaned and recreated on every start.
    No cleanup happens on exit (per the architecture plan).

REMAINING WORK

    template is updated to the new architecture (Phase 4). This PoC
    only validates server.js in isolation.
