================================================================================
C1-02 — ESBUILD DELIVERY FROM NUGET
================================================================================

Date:        2026-09-30
Status:      VERIFIED
Owner:       Implementation agent

GOAL
    Prove that a fresh project referencing TypescriptBridge.Build obtains
    esbuild and the Tool at a stable location without any manual step.

METHOD
    1. Create a fresh .NET project referencing TypescriptBridge.Build
       from a local artifacts NuGet source.
    2. Run dotnet restore.
    3. Run dotnet build.
    4. Verify the stable locations:
           obj/TypescriptBridge/tools/esbuild/win-x64/esbuild.exe
           obj/TypescriptBridge/tools/net8.0/any/TypescriptBridge.Tool.dll
    5. Verify Bridge.cs is generated.
    6. Verify debug and release JS payloads are generated.

RESULT
    All steps passed.
    No manual step was required.
    No developer machine-specific path was needed.

DELIVERY MODEL CHOSEN
    Model A. The Build package ships esbuild at tools/esbuild/win-x64/.
    An MSBuild target (TypescriptBridgePrepareTools) copies the package
    payload to obj/TypescriptBridge/tools/ before TypescriptBridgeGenerate
    runs.

FILES INVOLVED
    src/TypescriptBridge.Build/build/TypescriptBridge.Build.targets
    src/TypescriptBridge.Build/TypescriptBridge.Build.csproj
    artifacts/TypescriptBridge.Build.1.0.1.nupkg

NOTES
    A first attempt failed because NuGet served a cached older version
    of the package from %USERPROFILE%\.nuget\packages\typescriptbridge.build.
    Clearing the cache and re-restoring resolved this. Future
    experiments must clear this cache when the package version does
    not change but the contents do.
